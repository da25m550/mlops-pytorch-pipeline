What We're Building

This assignment walks through the complete ML deployment lifecycle for a CIFAR-10 image classifier — from raw Python code to a scalable, containerised, Kubernetes-orchestrated production service.

🧠

PyTorch Model

ResNet-18 adapted for 32×32 CIFAR-10 images. Trains to ~85% val accuracy on CPU.

Kubernetes

Training Job, Serving Deployment, Service, ConfigMap, PVCs, HPA.

🌐

REST API

FastAPI server: POST /predict returns class probabilities, GET /health.

🔬

Tests

Workspace Setup — Disk Quota Fix

⚠️
Important for shared Linux machines: If your home directory (/usr2/asreeniv/) has a disk quota, pip will fail with Errno 122: Disk quota exceeded when downloading PyTorch. Follow these steps to redirect ALL pip activity to the workspace (/local/mnt/workspace/asreeniv/).
1

Clean up partial install from home directory

# Remove anything pip partially wrote to the quota-limited home dir
rm -rf /usr2/asreeniv/.local/lib/python3.10/site-packages/
rm -rf /usr2/asreeniv/.local/lib/python3.10/
rm -rf /usr2/asreeniv/.cache/pip
# Verify home is clean
du -sh /usr2/asreeniv/.local/ 2>/dev/null || echo "Already clean"
2

Create workspace directories & symlink home → workspace

# Create workspace dirs for pip
mkdir -p /local/mnt/workspace/asreeniv/.local
mkdir -p /local/mnt/workspace/asreeniv/.cache/pip

# Back up existing home dirs (if any)
[ -d /usr2/asreeniv/.local ] && mv /usr2/asreeniv/.local /usr2/asreeniv/.local.bak 2>/dev/null || true
[ -d /usr2/asreeniv/.cache ] && mv /usr2/asreeniv/.cache /usr2/asreeniv/.cache.bak 2>/dev/null || true

# Symlink ~/.local and ~/.cache → workspace
ln -sfn /local/mnt/workspace/asreeniv/.local  /usr2/asreeniv/.local
ln -sfn /local/mnt/workspace/asreeniv/.cache  /usr2/asreeniv/.cache

# Verify symlinks
ls -la /usr2/asreeniv/.local
ls -la /usr2/asreeniv/.cache
3

Create Python venv inside workspace

cd /local/mnt/workspace/asreeniv/mlops
# Remove any broken venv from previous attempts
rm -rf .venv
# Create fresh venv
python3 -m venv /local/mnt/workspace/asreeniv/mlops/.venv
source /local/mnt/workspace/asreeniv/mlops/.venv/bin/activate
# Confirm venv points to workspace
which python   # → /local/mnt/workspace/asreeniv/mlops/.venv/bin/python
which pip      # → /local/mnt/workspace/asreeniv/mlops/.venv/bin/pip
4

Set pip cache to workspace & install CPU-only PyTorch

# Redirect pip cache (avoids home quota)
export PIP_CACHE_DIR=/local/mnt/workspace/asreeniv/.cache/pip
echo 'export PIP_CACHE_DIR=/local/mnt/workspace/asreeniv/.cache/pip' >> ~/.bashrc

pip install --upgrade pip

# CPU-only PyTorch (~200 MB, no CUDA packages)
pip install \
    torch==2.3.1+cpu \
    torchvision==0.18.1+cpu \
    --index-url https://download.pytorch.org/whl/cpu

# Remaining dependencies
pip install \
    PyYAML==6.0.2 numpy==1.26.4 Pillow==10.4.0 \
    tqdm==4.66.4 pytest==8.3.2 pytest-cov==5.0.0
5

Verify & run training

python -c "import torch; print('torch:', torch.__version__)"
torch: 2.3.1+cpu
python -c "import torchvision; print('torchvision:', torchvision.__version__)"
torchvision: 0.18.1+cpu

# Check disk usage is in workspace, not home
du -sh /local/mnt/workspace/asreeniv/mlops/.venv/

# Run training
cd /local/mnt/workspace/asreeniv/mlops
python src/train.py --config configs/training_config_local.yaml
ℹ️
Future sessions: Always reactivate with:
source /local/mnt/workspace/asreeniv/mlops/.venv/bin/activate
export PIP_CACHE_DIR=/local/mnt/workspace/asreeniv/.cache/pip

Part C — Docker Containerisation

30 pts
1

Build training image (multi-stage)

docker build -f docker/Dockerfile.train -t mlops-train:v1 .
# First build: ~10-15 min. Subsequent builds: ~30 s (layer cache)
docker images mlops-train
2

Build serving image (CPU-only, slim)

docker build -f docker/Dockerfile.serve -t mlops-serve:v1 .
docker images mlops-serve
3

Run training container

mkdir -p data checkpoints
docker run --rm \
  -v $(pwd)/data:/app/data \
  -v $(pwd)/checkpoints:/app/checkpoints \
  mlops-train:v1
# Checkpoint saved to ./checkpoints/classifier_v1.pt when done
4

Run serving container & test

docker run --rm -p 8080:8080 \
  -v $(pwd)/checkpoints:/app/checkpoints \
  mlops-serve:v1 &

# Wait ~10 s for startup, then test
curl http://localhost:8080/health
python3 -c "from PIL import Image; Image.new('RGB',(32,32),(100,150,200)).save('test_image.png')"
curl -X POST http://localhost:8080/predict -F "image=@test_image.png"

Part D — Kubernetes Training Job

10 pts
1

Start Minikube

minikube start --cpus=4 --memory=8192 --driver=docker
kubectl cluster-info
kubectl get nodes
2

Load images into Minikube

# Build directly inside Minikube's Docker daemon (recommended)
eval $(minikube docker-env)
docker build -f docker/Dockerfile.train -t mlops-train:v1 .
docker build -f docker/Dockerfile.serve -t mlops-serve:v1 .
# Verify
minikube image ls | grep mlops
3

Apply namespace, ConfigMap, and Training Job

kubectl apply -f k8s/namespace.yaml
kubectl apply -f k8s/configmap.yaml
kubectl apply -f k8s/training-job.yaml

# Verify PVCs created
kubectl get pvc -n ml-training

# Stream training logs
kubectl logs -f job/cifar10-training -n ml-training

# Wait for completion
kubectl wait --for=condition=complete job/cifar10-training -n ml-training --timeout=3600s
⏱
Training on CPU inside K8s takes ~30–60 min. To speed up, edit k8s/configmap.yaml and set epochs: 3 before applying.

Troubleshooting

ProblemFix
docker: permission deniedRun sudo usermod -aG docker $USER && newgrp docker
Training very slow on CPUSet epochs: 3 in configs/training_config_local.yaml
Minikube out of memorySet batch_size: 32 in k8s/configmap.yaml
ImagePullBackOff in K8sRun eval $(minikube docker-env) then rebuild images
Port 8080 already in useRun sudo lsof -i :8080 then kill the PID
kubectl can't find clusterRun minikube start first
Checkpoint not found in K8sCheck job completed: kubectl get job -n ml-training
pip install SSL errorRun pip install --trusted-host pypi.org -r requirements/train.txt
Serving pod stuck in PendingCheck resources: kubectl describe pod <name> -n ml-training
GitHub push rejectedSet up SSH key or use git config --global credential.helper store
